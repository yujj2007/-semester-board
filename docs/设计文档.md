# 学期任务站 · 设计文档

> 版本 v0.1 ｜ 公开只读 + 作者可写 + 弹幕评论的学期 DDL 看板

## 1. 目标与角色

一个**公开、开放、可互动**的网址，用来汇总本学期要参加的学习任务及其截止时间（DDL）。

| 角色 | 能否查看 | 能否改任务 | 能否发弹幕 |
|---|---|---|---|
| 作者（你） | ✅ | ✅ 增 / 删 / 改 | ✅ |
| 其他人（游客） | ✅ | ❌ | ✅ |

原则：**权限由数据库强制执行**，不是把按钮藏起来。别人改了前端代码也写不进数据。

## 2. 技术选型

| 层 | 方案 | 说明 |
|---|---|---|
| 前端 | 原生 HTML / CSS / JS，**零构建** | 不需要安装 Node；改完文件直接推 GitHub |
| 数据/后端 | **Supabase**（Postgres + Auth + RLS + REST） | 免运维；anon key 可公开，权限靠 RLS |
| 托管 | **GitHub Pages** | 推送即发布 |
| 弹幕 | 自研轻量引擎 | 多轨道调度 + Web Animations API |
| 外部依赖 | **无**（不加载任何第三方 JS/CDN） | 国内也可稳定打开，长期“永不失效” |

> 为什么不用 supabase-js？因为它在 CDN 上，国内偶尔打不开。这里直接用浏览器原生 `fetch` 调 Supabase 的 REST 接口，零依赖、更“永久”。

## 3. 数据模型

**tasks**（任务）
`id, title, course, detail, ddl(timestamptz), priority(high/mid/low), status(todo/doing/done), tags[], sort_order, repeat_rule, weekday, created_at, updated_at`

任务分两类，靠 `repeat_rule` 区分，**在同一张表里**存储：

| 类型 | repeat_rule | 说明 |
|---|---|---|
| 一次性任务 | `''`（默认） | 有明确 DDL，完成即归档沉底 |
| 每周持续任务 | `'weekly'` | 长期重复出现，不用每周重新添加；`weekday`（1=周一…7=周日，可空）用于排序与「下次」提示 |

> 旧数据没有这两个字段也没关系：前端 `normalizeTask` 会补默认值，**不会因为字段缺失而报错**。

**activities**（班会活动 · 独立表，与学习任务完全分开）
`id, title, activity_at, location, category, detail, tags[], created_at, updated_at`

**comments**（弹幕）
`id, nickname, content, color, is_hidden, created_at`

**site_config**（站点配置，键值对）
`title, semester, announcement …`（以后加字段无需改表结构）

## 4. 权限模型（RLS + 多作者 / 权限相同）

**作者名单**存在 `authors` 表，一行为一个人：

| 字段 | 含义 |
|---|---|
| `email` | 登录邮箱（主键） |
| `name` | 显示名，仅备注用 |
| `created_at` | 加入时间 |

**规则很简单：在名单里 = 作者 = 能编辑全部内容。** 作者之间没有高低之分，也不分模块。

判定函数（`security definer`，绕过 RLS 读名单，避免策略递归）：

- `auth_email()` —— 当前登录者邮箱
- `is_author()` —— 是否在名单里
- `my_caps()` —— 返回 `{ email, author }`，前端据此显示/隐藏编辑按钮（走 RPC）

| 表 | SELECT | INSERT | UPDATE / DELETE |
|---|---|---|---|
| tasks | 所有人 | 作者 | 作者 |
| activities | 所有人 | 作者 | 作者 |
| comments | 所有人（隐藏的仅作者可见） | 任何人 | 作者 |
| site_config | 所有人 | — | 作者 |
| authors | 作者 | — | 作者 |

**关键点**：权限在数据库层强制执行。前端只决定"该不该显示按钮"；即使有人改了前端代码，非作者的写操作照样会被数据库拒绝。

## 5. 页面结构

```
顶栏：班级名（大标题，作者可点 ✎ 修改）· 学期 · 同步状态 · [作者登录]
公告（可在 site_config 改）
标签页：[学习任务] [班会活动] —— 点击切换，默认停在上次浏览的模块
概览：随当前模块变化
  · 学习任务：一次性任务 / 临近(≤3天) / 已逾期
  · 班会活动：活动总数 / 即将开始 / 7 天内 / 已结束
面板①「学习任务」
  每周任务：长期、每周重复的任务独立成区（按星期排序，显示「下次」）
  任务清单：搜索
          排序：未逾期（按 DDL 升序）→ 已逾期（最近的在前，沉底）
          倒计时按「日历天」：DDL 当天 =「今天截止」，次日 =「还有 1 天」
          逾期 ≤4 天：留在清单底部；逾期 >4 天：移入「已逾期」折叠区（可展开查看）
          临近 DDL 高亮；逾期红色；作者可点行编辑
面板②「班会活动」
  活动列表：搜索 · 按时间排序（未结束在前，已结束沉底并变淡）
           显示类型 / 地点 / 标签 / 时间；作者可点行编辑
弹幕区（常驻底部，两个模块共用）：舞台（弹幕飞过）+ 输入框
        「查看最近的评论」文字版（无障碍）
```

## 6. 弹幕实现

- 提交后**乐观显示**（立即飞出），以落库成功为准；失败弹 Toast。
- **多轨道调度**：按屏高切分轨道，选择“尾部已清空”的轨道，避免重叠。
- 速度恒定（像素/秒），长文按宽度计算时长，阅读体验一致。
- **刷新回放**最近 N 条（`config.site.danmakuReplay`），舞台不空。
- 尊重 `prefers-reduced-motion`：自动切换为**静态标签**显示，不再滚动。
- 一律 `textContent` / 转义渲染，**杜绝 XSS**。

## 7. “刷新永不坏”的健壮性

1. **缓存兜底**：每次成功同步都写入 `localStorage`；刷新时先渲染缓存，再拉云端。
2. **不白屏**：断网/后端挂时显示缓存内容 + 顶部黄色横幅，绝不空白报错。
3. **自动重试**：云端轮询失败按**指数退避**（15s → 最长 120s），恢复后自动变绿。
4. **数据容错**：`normalizeTask/normalizeComment` 过滤脏数据；非法字段用默认值，**不会因一条坏数据整页崩**。
5. **未知字段忽略**：以后给后端加字段，旧页面照常运行。
6. **多标签同步**：本地模式监听 `storage` 事件，两个窗口同时开也能同步。
7. **全局兜底**：`window.onerror` / `unhandledrejection` 只记录不崩；每个渲染模块独立 `try/catch`。
8. **会话过期**：只影响作者的写操作，读者完全不受影响。
9. **实时推送 + 轮询兜底**：优先用 Supabase Realtime（原生 WebSocket）即时收到数据库变更；连不上或掉线时**静默回退**到 15 秒轮询，并带指数退避。两者互不干扰，最坏情况只会"慢一点"，不会出错。
10. **静态资源版本号**：`index.html` 引用 css/js 时带 `?v=1`；更新网站后把它 +1，即可强制所有访客（含手机浏览器缓存）拿到新文件。

## 8. 可扩展性（应对后续新需求）

- **配置驱动**：站点名/学期/公告存在 `site_config`，改数据即改页面。
- **功能开关**：`src/config.js` 的 `featureFlags`（弹幕、日历、导出 .ics…）。
- **模块化**：加功能 = 新增一个 `src/xxx.js` 并在 `index.html` 引入，不动老代码。
- **数据库迁移**：`schema.sql` 用 `if not exists` / `drop policy if exists`，可反复执行、安全叠加。
- **预留方向**：DDL 提醒/邮件、附件上传、打卡统计、多学期切换、日历视图。

## 11. 移动端适配

- **响应式布局**：`≤720px` 收窄工具栏、任务卡片换行；`≤560px` 顶栏改为两行、加大按钮点按区域。
- 已实测 **360 / 390 / 414** 三种手机宽度，**无横向溢出**。
- 输入框保持 16px 字号，避免 iOS 聚焦时自动放大页面。
- `viewport-fit=cover` + `env(safe-area-inset-*)`，适配刘海屏与底部横条。
- 弹幕舞台高度用 `clamp()` 随屏高自适应；点击区域不小于 ~27px，便于手指操作。

## 12. 已知限制 / 后续可加强

- **反刷屏**：目前有长度限制与作者隐藏；更强的限流可后续加 Supabase Edge Function（按 IP + 时间窗）。
- **Supabase 免费项目 7 天不活跃会暂停**：每月登录一次控制台即可唤醒；或改用 Cloudflare/Firebase。
- **实时性**：当前用轮询（15s）保证“永不坏”；后续可叠加 Supabase Realtime WebSocket 做秒级推送，轮询保留为兜底。
