# 部署指南

三种状态，按需选：

- **A. 先本地预览**（现在就能看，不用注册任何账号）
- **B. 接上 Supabase**（获得“作者可写 + 云端共享”）
- **C. 发布到 GitHub Pages**（获得公开网址）

---

## A. 本地预览（本地演示模式）

1. 直接双击打开 `semester-board/index.html`。
2. 站点会以**本地演示模式**运行：内置 4 条示例任务，数据存在你本机浏览器里，**刷新不丢**。
3. 点右上角「作者登录」，密码输 **`admin`**（见 `src/config.js` 的 `demoAdminPassword`），即可体验增删改。
4. 弹幕区输入文字发送，会立即飞过；「查看最近的评论」里能看到文字版。

> 本地模式仅用于预览，不联网、别人看不到。要让别人也能访问，请继续 B + C。

---

## B. 接入 Supabase（约 5 分钟）

### 1. 建项目
1. 打开 https://supabase.com 注册/登录 → **New project**。
2. 填项目名、设置数据库密码（自己记好）、选一个区域（建议新加坡/东京）。
3. 等 1～2 分钟项目初始化完成。

### 2. 建表
1. 左侧 **SQL Editor** → New query。
2. 打开 `supabase/schema.sql`，**先把 `is_admin()` 里的 `you@example.com` 改成你的邮箱**，然后整段复制粘贴进去 → **Run**。
3. 看到 `Success` 即完成。

### 3. 建作者账号
1. 左侧 **Authentication** → **Users** → **Add user** → **Create new user**。
2. 填**邮箱**（必须和上一步 `is_admin()` 里写的一致）和密码。
3. 勾选 **Auto Confirm User**（否则需要先点邮件里的确认链接）。
4. 保存。

### 4. 把密钥填进前端
1. 左侧 **Project Settings** → **API**。
2. 复制 **Project URL** 和 **anon public** key。
3. 打开 `src/config.js`，填入：
   ```js
   supabaseUrl: "https://xxxxxxxx.supabase.co",
   supabaseAnonKey: "eyJhbGciOi...（很长一串）",
   ```
4. 重新打开/刷新网站，右上角状态变为「云端 · 已同步」。
5. 点「作者登录」，用第 3 步的邮箱密码登录，即可增删改任务。

> `anonKey` 是**公开密钥**，可以安全放进前端代码；真正的写权限由数据库 RLS 控制。

---

## B2. 让其他人（如学习委员）也能编辑

本版本**不区分模块权限**：只要进了作者名单，就能编辑全部内容（学习任务、班会活动、评论）。

**第 1 步：给他建账号**
Supabase → **Authentication → Users → Add user** → 填**他的邮箱** + 一个密码，勾选 **Auto Confirm User**。把邮箱密码告诉他。

**第 2 步：把他的邮箱加进 `authors` 表**
Supabase → **Table Editor → authors → Insert row**，或直接执行：

```sql
insert into public.authors (email, name) values
  ('xuewei@example.com', '学习委员')
on conflict (email) do nothing;
```

**第 3 步：他用你的网站地址打开 →「作者登录」→ 输入自己的邮箱密码。**

登录后即可添加 / 编辑学习任务和班会活动，也能隐藏评论。

> 想收回权限：删掉 `authors` 表里那一行即可。

---

## C. 发布到 GitHub Pages

1. 在 GitHub 新建一个仓库（public），例如 `semester-board`。
2. 把 `semester-board/` 里的**全部文件**上传到仓库根目录
   （即仓库根下直接是 `index.html`、`assets/`、`src/` …）。
3. 仓库 **Settings → Pages**：
   - **Source** 选 `Deploy from a branch`
   - **Branch** 选 `main`，目录选 `/ (root)` → Save。
4. 等 1 分钟左右，网址形如：`https://你的用户名.github.io/semester-board/`

### 以后要更新网站
直接改文件、重新上传（或 `git push`）即可，1 分钟后线上自动更新。**刷新不会丢数据**，因为数据在 Supabase。

> ⚠️ **改了 css/js 后**：把 `index.html` 里所有 `?v=1` 改成 `?v=2`（下次 `?v=3`，依此类推）再上传。这样能让**所有人（含手机浏览器）**立即拿到新文件，而不是旧的缓存版本。

### 手机访问
同一网址在手机上直接打开即可（已做响应式适配）。发给同学时把网址生成二维码或用微信/QQ 发送都很方便。

## 常见问题

**Q：别人能加任务吗？**
不能。任务表的写权限只给作者账号，RLS 在数据库层拦截。

**Q：刷新会不会丢数据 / 报错？**
不会。数据在 Supabase；页面每次成功同步都会本地缓存一份，断网时显示缓存并提示，不白屏。

**Q：免费项目久没人访问会怎样？**
Supabase 免费项目 **7 天不活跃会被暂停**，每月登录一次控制台即可唤醒。

**Q：怎么改站点标题 / 学期 / 公告？**
在 Supabase 的 `site_config` 表里改 `title`、`semester`、`announcement` 的 `value`，刷新即生效。

**Q：后台要加字段（以后加需求）会不会把旧页面弄坏？**
不会。前端会忽略不认识的字段；表结构用 `if not exists` 可安全叠加。

**Q：想再加一个作者（如学习委员）？**
见 **B2 节**。要点：先在 Authentication 里给他建账号，再把他的邮箱写进 `authors` 表。不需要改任何前端代码。

**Q：不同的人能限制不同权限吗？**
本版本故意**不做**区分 —— 作者之间权限相同，都能编辑全部内容。这样最省事；将来若要区分，可以再加权限位。

**Q：我已经跑过一遍 schema，又加了新功能怎么办？**
直接把最新的 `supabase/schema.sql` **再整段 Run 一次**即可。脚本用 `if not exists` / `add column if not exists` / `drop policy if exists` 写法，**可反复执行**，不会破坏已有数据。
